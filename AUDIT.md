## Approved changes and tradeoffs

- Restored the shared Advisor navigation link's default Next.js prefetch behavior; no other link changed. The [isolated prefetch checkpoint](FE10-Evidence-Before-20261102/prefetch-experiment-checkpoint.md) measured approximately 89.4 KiB less home JS transfer with prefetch disabled, but the first Lace → Advisor transition was approximately 1.06 seconds slower under matched local production-build conditions. No Lighthouse improvement was established. The developer rejected this tradeoff.
- Added a focus-visible “Skip to main content” link before the header. Its native fragment target is the focusable `main`, so activation moves focus past repeated navigation and the next Tab reaches the first content link. The link is visually offscreen except while keyboard-focused; it adds no persistent layout space or client component.
- Added a separate, visually hidden polite live region for newly generated Advisor answer text. It announces a complete sentence when possible, otherwise a roughly 180-character word-bounded batch, at most once per 1.5 seconds during streaming. A short trailing fragment is announced after completion. Only newly received text is announced, not the growing full answer or prior conversation. Pending batches are canceled on Stop or error and reset for a new response. This trades a small announcement delay for fewer token-level interruptions; actual speech timing varies by screen reader. The visible stream, status line, Stop button and composer focus logic remain unchanged.
- Shortened the Home hero image alternative text from 105 to 75 characters while retaining the woman, embroidered lace, matching headwrap, and **illustrative** status. The original WAVE long-alt alert was a human-review prompt rather than an error; removal by WAVE has not yet been rechecked.
- Added component and browser regression tests for announcement batching/cancellation, skip-link focus movement, Lace dialog focus restoration and 375px page fit.

## Lace eager-loading trial — 2026-11-03 (retained by developer decision)

The developer approved one narrow experiment: `loading="eager"` was added only to the above-the-fold preview image in `app/lace/lace-photo-zoom.tsx`; its existing `fetchPriority="high"` remains. The zoom-dialog image is still mounted only after opening the dialog. No image file, quality, dimensions, styles, dependencies, Advisor code or prefetch setting changed. The [before and after JSON](FE10-Lace-Eager-Experiment-20261103/) records SHA-256 hashes: the Lace source changed, while the Advisor, root layout, global CSS and shared-header files were byte-identical in both builds. A [reverse patch](FE10-Lace-Eager-Experiment-20261103/before-from-trial.patch) applies cleanly to the trial and restores the exact before source for another build. The original before Lace file is also present at commit `53f6bba`.

Both variants passed `npm run build` and were served by `next start` on localhost:3103. The same Chrome 156.0.8078.4 headless script used three fresh-context runs per variant, 412 × 823 CSS pixels, DPR 1.75, 4× CPU slowdown, 150 ms latency, 204,800 B/s down, 84,375 B/s up, disabled browser cache and a warmed local image optimizer. These are **local production-build diagnostics, not Lighthouse scores or production measurements**. Raw individual runs and exact conditions are in [before.json](FE10-Lace-Eager-Experiment-20261103/before.json), [after.json](FE10-Lace-Eager-Experiment-20261103/after.json), and the [measurement script](FE10-Lace-Eager-Experiment-20261103/measure.mjs).

The before Lace runs included one marked outlier: 5,124 ms LCP versus 1,932 ms in the other two; both transition sets also had a slow second run. Three-run medians limit but do not eliminate this variability. Eager loading **did** move the request earlier, but it did **not** move the image response completion or LCP earlier in these local initial-load runs. Earlier image transfer can compete with JS and other resources. The navigation image-ready result favors the trial, while the initial-load LCP and blocking proxy do not. This is preliminary evidence, not a causal claim or a final retain/revert decision.

All three runs in both variants loaded the preview, kept `fetchpriority="high"`, showed no document overflow at 412px, opened the dialog, switched Zoom in to Fit image and restored focus after Escape. The dialog image was absent before opening. A [trial screenshot](FE10-Lace-Eager-Experiment-20261103/after-lace-412px.png) was visually inspected; the photographed fabric remained visible without apparent distortion. No matched before screenshot was captured. After the change: Vitest 15/15, existing server tests 28/28, existing UI checks 8/8, Playwright 3/3, lint, `tsc --noEmit`, production build and `git diff --check` passed. The Playwright server's `NO_COLOR`/`FORCE_COLOR` warnings were environmental, not test failures.

The earlier trial isolated only the eager prop and found an earlier request but **no established LCP improvement**. The later matched released-versus-final-candidate Lighthouse comparison below includes several FE-10 changes, so it cannot isolate eager loading. Its Lace median performance is lower and TBT higher in the candidate, but the slow-CPU warnings and run spread prevent a firm causal claim. The developer has approved retaining eager loading as the intended strategy for the identified LCP preview; no 83-to-90 production-to-local improvement is attributed to it. Post-change WAVE, real screen-reader checks and comparable deployed after-audits remain pending.

The human-reported keyboard result is **separate from automation**: “On the local homepage, Tab revealed Skip to main content; Enter moved into main content; the next Tab reached Explore Lace.”

## Final verification, limitations and release review

After the last source edit, `npm test` passed 15/15, `npm run test:existing` passed 28/28 server and 8/8 UI checks, `npx playwright test` passed 3/3, `npm run lint` passed, `npx tsc --noEmit` passed, `npm run build` passed with 26/26 static pages generated, and `git diff --check` passed. Playwright emitted only the `NO_COLOR`/`FORCE_COLOR` environment warning. Git emitted LF/CRLF conversion notices, not whitespace errors. Pinned Lighthouse's temporary installation emitted an unrelated OpenTelemetry deprecation warning and did not change `package.json` or the lockfile.

The [keyboard journey](FE10-Evidence-After-20261103/keyboard-journey-result.json) used a development-only slow-response fixture and passed 32 checks with no uncaught page errors. It verified 320/375/768/1280px document fit on Home, Lace, Advisor and Bag Studio, keyboard-visible Skip, focus on `main`, Explore Lace, dialog Escape/focus restoration, keyboard navigation to Advisor, keyboard Send/Stop with composer focus restored, safe return to the tailoring link **without clicking or sending an enquiry**, and Bag Studio color selection. The existing component/browser tests verify batched live-region DOM updates, including the final short fragment, and cancellation on Stop/error. This is not observed screen-reader speech. Bag Studio 3D orbit/zoom and physical Safari were not retested in this FE-10 pass; no Bag Studio source changed.

Outstanding checks: fresh WAVE on the **post-alt Home state** and on the **open Lace dialog** and **Advisor response/error states**; real screen-reader speech for batching, final fragment, completion, Stop and errors; physical mobile Safari; and comparable deployed after-audits only after release approval. Neither axe nor Lighthouse replaces WAVE. The first-run local WAVE screenshots above are valid only for their initial states. No FE-10 production deployment, commit, push or PR was performed.

**Review status:** the functional/accessibility candidate is ready for developer review, but FE-10 is **not ready to be declared complete or release-approved**: the matched local performance medians miss 80, all runs have a slow-CPU warning, interactive WAVE and screen-reader checks are outstanding, and there are no deployed after scores. The developer has chosen to retain Lace eager loading without claiming a gain; the performance threshold remains unresolved.
